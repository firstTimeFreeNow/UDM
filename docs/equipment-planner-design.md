# 装備条件・強化ロードマップの機能設計

## 1. 目的

キャラクター・戦闘タイプと現在装備を入力し、選択したコンテンツの装備条件との差分、部位別の強化方法、必要費用、資金を賄うまでの週数を表示する。

## 2. 対象範囲

- 目標は[対象18コンテンツ](content-requirements.md)から一つ選ぶ。
- 判定対象は装備能力値、特定装備の補正条件、テシスコア条件とする。
- 覚醒、極限、スキル、エタの意志、前提クエスト、キャラクターレベルは判定しない。結果は「装備・コア条件の達成」として表示する。
- 通常装備の選択候補は装備条件レベル310以上に加え、アクィルス・インファーナルを含める。エフェクト装備は、強化上限255以上のものをレベルにかかわらず含める。
- 神鳥・ルナリアレリック、カフスは、現在能力値と育成による増分を扱う。育成費用・育成期間は計上しない。
- 聖物は集計・強化提案の対象外とする。
- 装備更新の購入・売却・継承費用、素材の収集期間、複数目標の達成順、週課報酬の自動集計は対象外とする。

## 3. 画面と入力

同一のプランナー画面で次の順に操作する。UIにはshadcn/uiを使用し、説明文は操作と数値の意味に限定する。

| 順序 | 入力・表示 | 内容 |
| --- | --- | --- |
| 1 | 目標 | コンテンツ・難易度 |
| 2 | キャラクター・戦闘タイプ | 主能力値を自動決定 |
| 3 | 現在装備 | 部位、装備名、実数値、エンチャント内訳、合成回数、インクリ回数 |
| 4 | コア | 入力を有効にした場合のみ、対象地域・装着位置・能力タイプ・進化・強化段階 |
| 5 | 強化設定 | 装備ごとのビアヌ／エタ、使用呪文書、単価、所持数、20%割引 |
| 6 | 資金・収入 | 初期資金、週間上限、週間収入、週間予算、臨時収入 |
| 7 | 結果 | 条件との差分、強化案、費用内訳、週ごとの資金見通し |

サイドバーはページ内スクロールではなく入力画面の切り替えに使用し、選択中のカテゴリのみ表示する。画面を切り替えても入力・開閉状態・比較結果を保持する。計算結果は入力画面とは独立した常設領域とし、PCの広い画面では入力の右側へ配置する。計算結果画面を選ぶと結果を全幅で表示する。装備差し替え比較は独立した画面とし、提案の編集時は現在装備画面へ切り替える。スマートフォンではセレクトメニューでカテゴリを切り替え、選択中の入力画面と計算結果を縦に配置する。

キャラの戦闘タイプが一つの場合は自動選択する。コアと所持品の入力は任意とし、コア欄は折りたたむ。価格・収入・目標を変更した場合は結果を再計算する。変更前の結果と変更後の結果を混同させない。

## 4. 能力値と条件判定

### 現在値

部位ごとにMR反映後の基礎値、選択したエンチャント、任意の強化値を保持する。実数値は「基礎値＋エンチャント」を装備上限で止めた値に、任意加算（アビリティ等）を加える。基礎値は編集可能にする。エンチャントの登録枠は追加・削除ボタンで増減でき、装備の合成回数・インクリ回数とは独立して入力する。登録枠の初期値のみ合成回数とインクリ回数から求め、装備の初期合成回数は詳細に配置する。

- 現在値の集計には実数値を一度だけ使う。
- 上限の既知・不明は能力値ごとに保持し、選択中の戦闘タイプで必要な能力値だけ確認する。例えばMR上限が既知なら、STAB等の上限が不明でもMRの計算は実行できる。不明な上限を0として表示しない。
- 将来値には、現在値から今後増える分だけを加える。
- エンチャントの選択・任意入力の変更は実数値へ即時反映する。呪文書の増分が装備上限を超える場合も使用でき、上限までの実増分で強化案と到達判定を行う。呪文書の購入単価は切り捨て前の商品として計上する。計算では実数値を使用し、強化値を二重加算しない。
- マジックルーレットの実行・費用最適化は行わない。

### 装着アビリティと強化目標上限

部位・装備レベルに対応し、固定補正または追加効果で選択中の主能力値を増やせるアビリティだけを名前の候補に表示する。固定補正は選択により自動加算する。追加効果は実際に付いた能力値・数値を候補範囲から選択する。能力値の追加効果は1枠とし、選択中のスタイルの主能力値だけを表示する。エンチャントの選択候補も同じ主能力値に絞る。STAB・HACK複合型は両方を候補にする。装備条件と無関係なダメージ率等は能力値へ加算しない。アビリティの補正は装備のエンチャント上限とは別枠で加算する。従来の手入力欄はその他の補正として保持する。

エフェクトに限り、強化案で目指す能力値の上限を設定する。初期値は255とする。他の部位は装備本来の上限を使用する。255・400・600・700・任意値を選択できる。提案は装備本来の上限と強化目標上限の小さい方までとし、アビリティ・その他の上限外加算は別枠で扱う。現在値は目標上限で切り捨てない。目標上限を設定したことだけを理由に装備更新を必須とはしない。

### 主能力値

[キャラクター・戦闘タイプ対応表](character-styles.md)からS、H、I、M、S＋H、H＋Iの式を選ぶ。複合値は対応能力値を合計して判定し、ダメージ計算の倍率は掛けない。

現在値をV、必要値をTとすると、不足は `max(T − V, 0)`、超過は `max(V − T, 0)`、達成率は `V / T × 100` とする。

特定装備の補正条件は総計と分けて判定する。神鳥からルナリアへの進化は同一部位の更新として扱い、二重加算しない。

### コア

コア補正は装備値に加算せず、地域別の条件として判定する。

| 状態 | 表示 |
| --- | --- |
| 装備・コアとも達成 | 対象の装備・コア条件を達成 |
| 装備達成・コア不足 | 装備条件達成／コア不足 |
| 装備不足 | 装備条件不足。コアの状態を別に表示 |
| コア条件あり・コア入力なし | コア未確認 |
| コア条件なし | コア判定不要 |

コア入力を有効にした場合は、各コアの進化・強化段階から育成手順と費用を求め、共通の資金計画に含める。素材の週間入手量は入力させず、素材収集の期間や未入力警告を追加しない。

### 称号

称号は1つ選択し、STAB・HACK・INT・MRの補正を装備合計へ加算する。ローカル資料のマスターを名前で検索でき、能力値は編集可能とする。一覧にない称号は手入力できる。称号を未装着にすると補正は0となる。称号はインクリ・エンチャントの対象に含めない。既存の保存データに称号がない場合は未装着として復元する。

### アバター装備

兜（Show Head）、頭（Show Face）、体（Show Back）、脚（Show Foot）、エフェクト（Show Effect）の5部位を管理する。装備中の各部位のSTAB・HACK・INT・MR実数値を通常装備とは別に加算する。入力値はアバター強化剤等による現在の強化分を含める。

5部位すべてが装備中かつ補正付きアバターのセット対象である場合、各能力値へ＋10を一度だけ加算する。未装備やセット対象外の部位がある場合、セット効果は加算せず、装備中の部位の実数値のみ集計する。補正付き5部位の一括設定では各部位の基本補正を各＋1とする。アバターはインクリ・エンチャントの提案対象に含めない。旧保存データは5部位未装備として復元する。

補正・セット効果は[Tale Wiki：鏡花水月](https://talewiki.com/?Item/Random/%B6%C0%B2%D6%BF%E5%B7%EE)を参照する。

## 5. 強化提案

現在装備の上限、合成回数、インクリ回数、使用方式、呪文書から、実行順を含む部位別の強化案を作成する。

- インクリはビアヌ・エタに限定する。
- 適用可否を装備単位で判定し、両方使える場合は選択可能にする。方式は装備ごとに指定する。
- 合成枠を空ける前にエンチャントを実行したことにしない。
- 呪文書の使用可否は商品単位で設定し、除外された商品は使わない。
- レリック・カフスの育成案には能力値の目標と増分を示し、育成費用は加算しない。

装備更新を必須として案内するのは、現在装備を育成しても目標へ到達できないと確定した場合に限る。費用や期間が大きいこと、予算不足、除外設定、データ不足だけを理由に装備更新を必須としない。

強化ロードマップは装備強化、レリック・カフス、テシスコアに分類する。装備ごとのカードに装備名、インクリ方式と必要成功回数、呪文書別の強化成功回数、能力値の前後を図示する。同じ呪文書を使う操作はまとめ、詳細の実行順は開閉して確認する。

比較結果には費用・期間・リスクの各観点を示す。各候補には期待費用と90%・95%予算を併記し、同じ案が複数観点で一致する場合は重複表示しない。リスクは失敗による支出・期間の上振れとして扱う。

### 装備差し替え比較

現在構成で達成可能な場合も、任意で装備差し替え案を自動提案する。キャラクターが装備可能なマスターから、現在装備の一段上の系列だけを改善候補として選ぶ。系列順はインファーナル→アクィルス→アビス→エクリプス→セイクリッド→改・セイクリッドとする。セイクリッド系の自動提案は、目標がルビコナのハード以降の場合に限る。現在の対象は追従する喜び（ハード）・見つめる悲しみ（ハード）とする。製作の前提となるコンテンツへの入場案にはセイクリッド系を使わず、空虚の領域・両ボスのノーマル・喜びの残像への入場案から除外する。系列の使用可否をユーザーに別途入力させない。系列を判定できない装備は自動提案から除外する。イベント装備や系列を飛び越えた装備は自動提案しない。マスターで対応関係を確認できる場合は同じ武器・鎧・腕装備の種類を維持する。1部位と複数部位の差し替えを比較する。変更する部位数、追加の強化費用、条件との差を基準に候補を提示する。候補探索は全組み合わせの最適解を保証しない。

比較元の装備構成を独立して保存し、目標・価格・収入・称号・アバター等の共通条件は現在の入力を両構成へ適用する。共通条件を変更した場合は古い提案を消して再計算する。提案した構成には変更部位、装備名の前後、装備合計、追加強化の期待費用、費用を賄う週数を表示する。提案を選択すると通常の装備入力欄で編集でき、再計算後の構成を比較できる。比較元へ戻す操作を用意する。

差し替え先の初期入力はマスターの基礎値・未強化状態とする。既存装備のエンチャント・アビリティを自動で移さない。装備の取得・売却・継承費用は計上しない。比較元の保存には既存入力と同じ検証を適用する。入力の初期化時は比較元も削除する。

## 6. 費用と通貨

費用はインクリの試行費用、呪文書購入費、入力を有効にしたコアの育成費用とする。商品代とゲーム内手数料を分け、所持品を追加購入数へ反映する。

ELSOとSEEDは別残高で管理する。ELSO払いが可能な操作ではELSOを優先し、当週の利用可能分で足りなければSEEDを使う。ELSO専用商品に必要な残高も考慮する。両通貨を自由に両替できるものとして扱わない。

20%割引はチェックで切り替える。割引対象のゲーム内手数料へ適用し、市場価格・素材数・成功率には適用しない。固定販売商品も手数料と区別する。最低費用と端数処理は操作別の費用ルールに保持する。

計算方法と初期価格は[強化・費用ルール](equipment-rules.md)に定義する。

装備別の費用内訳を各強化カードに常時表示し、インクリ費用・呪文書購入費・SEED/ELSOの支出を分ける。共有の所持品と支払配分を反映した同じ計算結果から集計し、全装備・コアの内訳合計を全体期待費用と一致させる。

## 7. 資金ロードマップ

### 入力

ELSO・SEEDごとに次を入力する。

- 強化に使える初期資金
- 毎週の収入見込み
- 毎週の強化予算
- 毎週の平均臨時収入
- 指定週の単発臨時収入

通常収入は合計を直接入力する。コンテンツの解放に合わせて自動で収入を増やさない。

### 週次計算

0週目は初期資金を使う。1週目以降は収入を加算し、強化費用へ充当し、未使用分を翌週へ繰り越す。

通常収入の入金額は毎週の収入見込みをそのまま使う。当週収入は週間予算まで配分し、予算超過分も保持して翌週から利用可能にする。過去の残高と臨時収入は当週予算への追加枠として扱う。

臨時収入は通常収入・週間予算とは別枠で加算する。単発収入は指定週のみ、平均臨時収入は毎週加算する。同じ入金や繰越分を二重計上しない。

### 表示

資金ロードマップは強化手順から分け、0週目から完成目安まで全週の日付・SEED・ELSO累計をページネーション付きの表で表示する。表示件数・ページ番号を指定でき、すべての週へ移動できる。週数は必要な強化費用を賄うまでの目安とし、素材収集の期間やプレイ時間を加えない。

期待費用・90%予算・95%予算それぞれの資金見通しを示す。入力した収入が実現する前提で計算し、所定の週に必ず強化が成功するとは表示しない。

## 8. データと保存

ゲームデータはTale Wiki等の参照情報から作成した静的マスターを使用する。値、単位、出典、適用条件を保持し、上限不明・操作不可・能力値なしを区別する。欠損値を0や無制限で補完しない。計算に必要な上限・適用条件を持つレコードを強化候補に使用する。

入力値はバージョン付きのlocalStorageへ保存し、ブラウザーを閉じた後も復元する。保存失敗、破損データ、形式変更を処理する。削除された装備IDを別装備へ自動置換しない。

保存対象は装備、コア、価格、候補設定、所持品、資金、収入とする。同一ブラウザーでの再利用を対象とし、端末間同期・ログイン・外部DBは設けない。入力値は外部へ送信しない。

## 9. 技術構成

Next.js App Router、TypeScript、pnpm、shadcn/uiを使用する。静的出力をGitHub Pagesで公開する。既存の検証ページは削除し、プランナーを `/equipment-planner/` に配置する。トップページにプランナーへの入口を設ける。

条件判定、候補生成、費用計算、週次計算は表示処理から分離する。計算結果には入力条件とマスターバージョンを対応付け、古い計算結果による上書きを防ぐ。

通貨・個数は整数の最小単位で保持する。確率は表示用の%と内部値を区別する。呪文書単価に32bit整数を使用しない。

公開はリリースPRのマージ、GitHub Release、GitHub Pagesへのデプロイの順で行う。

## 10. 受入条件

| 項目 | 条件 |
| --- | --- |
| 判定 | 主能力値・複合値・閾値一致・不足・超過を正しく扱う |
| 能力値 | MRによる実数値を保持し、既存エンチャントを二重加算しない |
| 装備 | Lv310を含め、禁止された操作・無効な合成順序を提案しない |
| インクリ | 成功後の回数別確率を適用し、装備破壊のある方式を使わない |
| 呪文書 | 対象能力・除外設定・成功時消費・毎試行消費を反映する |
| 費用 | 所持品、割引、最低費用、端数、複数部位の在庫共用を扱う |
| 確率 | 計画全体の分布から90%・95%予算を算出する |
| 資金 | 通常上限、予算、臨時収入、繰越、ELSO優先を反映する |
| コア | 装備値から分離し、入力しない場合は育成費用を作らない |
| 特別装備 | レリック・カフスの能力値を扱い、育成費用は計上しない |
| 装備更新 | 現在装備の育成で到達できる場合は更新を提案しない |
| 保存 | ブラウザー再起動後に復元でき、破損・形式変更を処理する |
| 公開 | 静的出力、直接URL、再読み込み、モバイル表示、トップページ・プランナーを検証する |

装備別の費用内訳は計算結果の合計直下に独立したカードとして一覧表示する。各カードに部位・装備名とインクリ・呪文書・コア育成の費用、SEED・ELSOの合計を表示し、強化ロードマップとは分けて配置する。

週数計算に520週の打ち切りは設けない。資金・収入と指定週の臨時収入から費用を賄える最初の週を求める。強化ロードマップに全体と部位ごとの完了目安を表示し、部位ごとの週は手順順の累積期待費用から求める。

完成時期は日本時間の当日を起点に、約何年・何か月後かと完成予定日を併記する。週数は補助情報として残す。手順ごとの期待支出には共有在庫とSEED・ELSO配分を反映し、累積支出を賄う週を予定週とする。部位別の時系列チャートと、時期・部位・インクリ成功回数・能力値増分・強化手順を含む一覧を表示する。チャートの各点から対象時期の強化内容を選択できる。

各装備に乗り換え予定を保持する。初期状態は未指定とし、既存入力も未指定として扱う。通常の強化には通常呪文書を使用し、使い捨てはすぐ乗り換える予定の装備か、その1回で装備本来の強化上限に達する場合に限る。コンテンツの入場条件やエフェクトの目標上限への到達を、使い捨ての使用理由にしない。装備差し替え案の新装備へ、比較元の乗り換え予定指定を引き継がない。

強化スケジュールは同じ週・同じ部位でも1操作を1行に分ける。作業・試行回数の期待値・支払いの実施順と1回の費用・SEED支出の期待値・ELSO支出の期待値を別の列で示し、合成回数の遷移を1セルに連結しない。ビアヌの各成功は現在のインクリ回数に応じた確率と費用で個別表示する。

強化チャートは初期状態で全期間・全部位の全景を表示する。日付範囲・部位で絞り込み、手順表と資金表はページネーションで閲覧する。表示件数は10・20・50・100件から選択する。

スケジュールの調整は部位別の実施順と開始日で行う。開始日の早い部位を先に、同日なら指定順で処理し、部位内の操作順は保つ。調整時は将来収入・共有在庫・ELSO優先の支払配分を含め費用と完成日を再計算する。設定は入力とともに保存する。インクリの手順はELSOで試行し、未成功かつELSOが1回分未満になった場合にSEEDへ切り替える順序で表示する。成功時は直ちに次の操作に進み、残金を引き継ぐ。両通貨とも不足する場合は次の収入を待ち、ELSOから再開する。各手順に1回の成功率と通貨別の1回の費用を示す。試行回数は前操作までの成否で変動するため固定しない。通貨別の期待支出は平均として区別し、支払指示額や固定の分配比率として扱わない。エタ・強化券・呪文書の所持品を優先し、購入が必要な場合の通貨と単価を区別する。
