# UDM 共通 URL 短縮設計（たたき台）

## 目的と範囲

UDM の各機能の正式なルートを維持し、共有時には短縮 URL を使えるようにする。
日程調整専用の仕組みにはせず、他の UDM 機能でも利用する。
利用料は無料プラン内とし、課金アカウントの登録を前提にしない。

初期対象は UDM 内の共有可能な画面。外部サイトの任意 URL 短縮は対象外とする案。
各画面の「共有リンクを発行」ボタンを参加者・管理者が利用できる。
転送先の入力や短縮コードの指定は不要で、現在の画面の有効なリンクを再利用し、なければ発行する。
繰り返し押しても同じ画面のリンクを重複作成しない。
一覧・任意コードでの作成・転送先変更・無効化は既存の管理画面 `/UDM/admin/links/` に残す。
管理画面への短縮リンクは初期登録・一般向け表示に含めない。
これらの範囲と管理方法は本設計の提案であり、実装前に確定する。

## 正式 URL と短縮 URL

正式 URL はサービスと画面の意味が分かる名称を使う。
日程調整の候補は `/UDM/afetiria-extra/`、`answer/`、`history/`、`admin/`。
正式ルート名は仮決めであり、短縮のために `/a/` などへ変更しない。

短縮 URL の候補は `/UDM/s/?c=<code>`。コードと正式ルートの対応を保存する。
これは新しい共有用転送ルートであり、既存の正式ルートの名前変更ではない。
GitHub Pages のドメインと `/UDM` は残るため、短縮効果はパス部分に限られる。
より短いドメインが必要な場合は外部サービス等を別途比較し、未承認で追加しない。
実在する短縮 URL は設計段階では発行していない。

## 静的ホスティングとの整合

Next.js の静的出力で固定の `/s/` ページを生成する。
ページがコードを取得し、対応表を読み取ってブラウザーで正式 URL に転送する。
アクセスのたびにサーバーで実行する HTTP 301/302 転送ではなく、JavaScript による転送となる。
登録のたびの再ビルドは不要とする。動的な `/s/[code]` の実行は前提にしない。
転送後は履歴を置換し、戻る操作で転送を繰り返さない。
不存在・無効・通信失敗では自動転送せず、理由に応じた案内を表示する。

## 保存・権限

スプレッドシート正本の構成へ変更したため、短縮対応表も管理用シートへ保存する案に変更する。
回答とは別の管理用ブックを候補とし、認証・権限検証を行うバックエンド経由で操作する。
公開解決用フィールドは `targetPath` と `enabled` のみとする。
管理用メモや実在する個人識別子は公開解決用ドキュメントに混在させない。
コードは推測困難な乱数から生成し、作成時に既存コードを上書きしない。
登録済みリンクを再利用し、対象週の更新ごとにリンクを増やさない。
無効化したコードを別用途に再利用しない。

短縮リンク自体は認証を回避する手段としない。
解決は未ログインでも可能とする。画面の共有にはログインと利用許可が必要。
一覧取得・任意転送先の編集は管理者に限定する。
公開され得る転送先にはキャラクター名・回答・認証情報を含めない。
日程調整の転送先では、参加者の認証とバックエンドでの権限検証を別途必須とする。

転送先は同一オリジンの許可済み UDM ルートに限定する。
外部 URL、スキーム付き URL、プロトコル相対 URL、短縮ルート自身を拒否する。
正規化後のパスを検証し、バックエンド側でも許可対象を制限する。
発行時の画面検証だけに依存しない。パスのエンコード・ループのテストを行う。

## 操作

ログイン済みの利用者が対象画面を選び、既存リンクを取得するか新規発行する。
共有対象の画面では、既に登録された短縮 URL をコピーできる設計を検討する。
登録情報を取得できない場合は正式 URL のコピーに切り替え、その旨を表示する。
アクセス解析・訪問者の追跡・アクセスごとのカウンター更新は初期対象外。

## 受入条件

- 正式ルートから直接開いても、短縮リンクから開いても同じ画面へ到達する。
- リンクは対象週が変わっても同じものを使える。
- 未認証の利用者は短縮リンクを経由しても日程調整データを取得できない。
- 参加者も各画面のボタンで共有リンクを発行・コピーできる。未ログインでは発行できない。
- 外部 URL や管理対象外のルートへ転送できない。
- 公開リポジトリとビルド成果物に資格情報やメンバー一覧を含めない。
