# 実装状況（2026-11-19）

## 実装した構成

- Next.jsの専用ルート `/UDM/afetiria-extra/` と、そのanswer/history/admin。
- 共通メール・パスワード認証と管理者Google認証、Firebase SDKでのログイン保持。
- メンバーIDだけのブラウザー保存。名前一覧・回答は権限確認後に取得する。
- ○/△/×/未回答の差分保存。再取得・60秒間隔・画面復帰時の取得でも下書きを保持する。
- 保存前の値による競合確認、保存結果が不明な場合の自動再送禁止。
- 開催候補、確定後の回答変更、条件未達時の表示。
- 管理者によるメンバー追加・必須条件変更・候補追加削除・開催日時確定。
- 開催履歴の概要を12件ずつ取得する。
- 各参加者画面の共有リンク発行・コピー。既存リンクを再利用し、参加者・管理者とも利用可能。
- 管理用の共有URL一覧 `/UDM/admin/links/` と転送 `/UDM/s/?c=CODE`。
- Apps ScriptのGit管理元とclaspによる反映・既存デプロイ更新のGitHub Actions。

既存トップと装備プランナーの内容はルートグループ`(tools)`へ移し、URLを維持している。
アフェティリアへの入口は既存トップへ追加していない。
Apps ScriptのHTMLは既存スプレッドシートのダイアログ用として保管する。
Web版はReactコンポーネント・共通RPCクライアント・Firebase初期化を分けて実装した。

## Apps Scriptと正本

元の設定・候補・回答管理・開催履歴を利用し、回答を別のDBへ複製しない。
Webと既存ダイアログの保存本体を共通化し、API・ダイアログ・週更新はScriptLockを使う。
最低人数はB5、上限は8。△を開催人数へ加算しない。
未開催週は翌月曜0時以降、確定週は開始から120分経過後に繰り越す。
既存の5分間隔トリガーの関数名を維持する。
手動候補を7日進め、数式の日付は数式を維持する。
履歴作成中断時のマーカーを先に設定し、再実行で重複保存・二重繰り越しを避ける。
旧Document Propertiesの未完了マーカーはScript Propertiesへ引き継ぐ。

初回設定はID列D13:D25とUDM共有リンクタブを追加する。
実シートのD列が未使用であることは読み取りで確認したが、実行時にも既存値を検証する。
所有者によるWebApi.gsのinitializeWebApp実行が完了し、ID列と共有リンクタブの作成を確認した。

## 本番接続の進捗と残る作業

Google Apps Script APIの有効化と所有者のclasp認可は完了。
実プロジェクトを取得し、main.gsが提供された元スクリプトと一致することを確認した。
反映前の版をバージョン1（Before UDM web API migration）として保存してから、
Git管理元のコードを本番プロジェクトへpushした。
所有者が本番プロパティ4項目を設定し、WebApi.gsのinitializeWebAppを実行済み。
本番Webアプリの初回デプロイも完了し、exec URLをローカルのNext設定へ登録済み。
本番APIの未認証ブラウザー通信を試したところ、Google側がHTTP 401を返しCORSで失敗した。
Apps Script APIで既存デプロイを読み取り、公開範囲がMYSELF（自分のみ）、
実行者がUSER_DEPLOYING（デプロイした所有者）であることを確認した。
この構成では公開範囲を全員へ変更し、アプリ内のFirebase認証・権限判定まで通信を通す必要がある。
所有者が新しいデプロイを作成し、ローカルのexec URLとデプロイIDを更新済み。
新URLで未認証ブラウザーPOSTはHTTP 200のJSONをCORS越しに取得できた。
初回は空トークンがAUTH_REQUIRED、不正トークンがCONFIG_REQUIREDとなった。
所有者がUDM_FIREBASE_PROJECT_IDを追加した後、同じURLで再試験し、
空トークン・不正トークンともAUTH_REQUIREDとなることを確認した。
両方の応答でHTTP 200・JSON・リクエストID一致を確認し、CORS越しに取得できた。
所有者がログイン後の読み取りとWebからの保存、双方向の同期を確認済み。
共有リンク発行用udm.links.shareを追加し、参加者権限で利用可能とした。
共有機能の反映時にバージョン4でWebアプリの公開入口が消え、接続障害が発生した。
原因はGit管理元マニフェストにwebapp設定がなく、手動デプロイの公開設定が保持されなかったこと。
webapp.access=ANYONE_ANONYMOUS、executeAs=USER_DEPLOYINGを明記し、
欠落・不一致を反映前に拒否する検査と回帰テストを追加した。
同一URLのバージョン5へ更新し、実デプロイの公開範囲・実行者と
ブラウザーPOSTのHTTP 200、JSON、リクエストID一致、AUTH_REQUIRED応答を再確認した。
復旧後の認証済み利用者による画面再確認は未実施。
管理操作は管理者の権限判定を維持し、回答データの書き換えによる試験は行っていない。

GitHubのRepository variablesは9項目の登録名と有効化・deploy設定を画像で確認した。
省略表示された値の全文とRepository secretのAF_CLASPRC_JSONは未確認。
所有者から設定完了の報告はあるが、Actionsでの認証・自動反映の成功確認はまだ行っていない。
具体的な設定と反映手順はintegrations/apps-script/afetiria/README.mdにまとめた。

## 制限

Apps ScriptのロックはGoogle Sheetsの人による直接編集を止めない。
人の同時編集との完全なトランザクションは保証せず、保存前比較は可能な範囲の検出となる。
既存シートの容量に合わせてメンバー12人・候補54件、共通短縮URLは200件を上限とする。
履歴は開催概要を表示する。過去週の回答全件表示・保存期間の自動削除は未実装。
本番配信元でのCORS・処理時間・無料枠の実測と、実トークンの失効動作は確認が残る。
短縮URLはJavaScriptで解決するため、HTTPの301/302リダイレクトではない。
